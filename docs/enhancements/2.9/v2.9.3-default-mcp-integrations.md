# v2.9.3 — Default MCP Integrations

**Created:** 2026-05-01
**Status:** Planning
**Priority:** MEDIUM — completes the MCP-server experience landed in v2.9.1 Phase 5

## Overview

Ship eleven Model Context Protocol servers as built-in defaults on every RTPI install: browser automation (Playwright, Chrome DevTools), HTTP fetch, filesystem, sequential-thinking, persistent memory, GitHub, code search (searchcode), Claude Task Master, Tavily web search, and arXiv. The v2.9.1 stack already provides the database-driven supervisor ([`server/services/mcp-server-manager.ts`](../../../server/services/mcp-server-manager.ts)), JSON-RPC liveness probe ([`server/services/agents/mcp-invoker.ts`](../../../server/services/agents/mcp-invoker.ts)), and REST surface ([`server/api/v1/mcp-servers.ts`](../../../server/api/v1/mcp-servers.ts)) — this release is purely a *seeding + managed-lifecycle* layer on top.

The work breaks into **5 phases**, all gated by `FF_DEFAULT_MCP_SERVERS` except the schema-only Phase 1. All schema changes are additive (consistent with v2.9.1's non-destructive principle). Servers requiring API keys (GitHub PAT, Tavily key) are seeded as rows but stay `status='stopped'` with a "Needs configuration" badge until their secrets are populated, so the install never fails because an upstream key is missing.

## Current State Analysis

### Existing Implementation

- [`shared/schema.ts:409-429`](../../../shared/schema.ts#L409-L429) — `mcpServers` table holds `name`, `command`, `args`, `env`, `status`, `pid`, `autoRestart`, `maxRestarts`, `restartCount`, `uptime`, `lastError`, `livenessPath`, `lastProbeAt`, `lastProbeOk`. Sufficient for any stdio-spawned MCP server.
- [`server/services/mcp-server-manager.ts`](../../../server/services/mcp-server-manager.ts) — singleton that spawns/monitors/auto-restarts any row; SIGTERM→SIGKILL escalation, 30s spawn timeout, 30s health check loop, boot-time `recoverErroredServers()`.
- [`server/services/agents/mcp-invoker.ts`](../../../server/services/agents/mcp-invoker.ts) — JSON-RPC 2.0 over stdio: `listTools`, `callTool`, `probe`. Writes `lastProbeAt`/`lastProbeOk` back to the row every 30 s.
- [`server/api/v1/mcp-servers.ts`](../../../server/api/v1/mcp-servers.ts) — full CRUD + start/stop/restart, role-gated (`[admin]` for writes, `[admin, operator]` for lifecycle).
- [`client/src/hooks/useMCPServers.ts`](../../../client/src/hooks/useMCPServers.ts) — `MCPServer` interface + `fetchServers/refetch`. Consumed today by `Agents.tsx`, `WorkflowBuilder.tsx`, `ImportAgentDialog.tsx`.

### What's Missing

- No built-in catalog: every install starts with zero MCP servers and admins must manually `POST /api/v1/mcp-servers` for each one.
- No managed-vs-user distinction: deleting a row is a one-way action; there is no "reset to defaults" or "reinstall" path.
- No bulk re-sync mechanism: when we extend the catalog in a future release, existing installs see nothing.
- No "needs configuration" surface: today a server with missing required env vars fails to spawn and lands in `status='error'` — no UI cue to the operator that the failure is configuration, not code.

## Engineering Scaffold — Phase 1: Schema scaffold + feature flag

- **Goal:** Add the `seed_key` UNIQUE column that every later phase keys off of, and register the gating feature flag.
- **Reuses:** existing `mcpServers` table; existing flag registry pattern in [`shared/feature-flags.ts`](../../../shared/feature-flags.ts).
- **Work items:**
  - [ ] Author additive migration `db/migrations/0039_add_mcp_seed_key.sql` adding `seed_key text` and `CREATE UNIQUE INDEX mcp_servers_seed_key_uniq ON mcp_servers (seed_key) WHERE seed_key IS NOT NULL` (partial index — preserves user-created rows that have no seed key).
  - [ ] Mirror the column in [`shared/schema.ts`](../../../shared/schema.ts) on the `mcpServers` definition (`seedKey: text("seed_key")`).
  - [ ] Add `defaultMcp: "FF_DEFAULT_MCP_SERVERS"` to `FEATURE_FLAGS` in [`shared/feature-flags.ts`](../../../shared/feature-flags.ts).
  - [ ] Document `FF_DEFAULT_MCP_SERVERS`, `GITHUB_PERSONAL_ACCESS_TOKEN`, `TAVILY_API_KEY` in `.env.example`.
- **API additions:** none (feature flag picked up automatically by `GET /api/v1/settings/features`).
- **Schema changes:** migration `0039_add_mcp_seed_key.sql` — `ALTER TABLE mcp_servers ADD COLUMN seed_key text` + partial unique index. No data movement.
- **Acceptance:**
  - `npm run db:push` succeeds; existing `mcpServers` rows unaffected (`seed_key IS NULL`).
  - `GET /api/v1/settings/features` returns `defaultMcp: false` until `FF_DEFAULT_MCP_SERVERS=true`.
  - Drizzle Studio shows the new column.
- **Effort:** S. **Flag:** none (additive schema).

## Engineering Scaffold — Phase 2: Default catalog + idempotent sync

- **Goal:** Define the 11-entry catalog in code and seed it into `mcp_servers` once at install time and again on every boot when the flag is on, so future catalog additions land without operator action.
- **Reuses:** [`shared/schema.ts`](../../../shared/schema.ts) `mcpServers`; [`scripts/enable-mcp-autostart.ts`](../../../scripts/enable-mcp-autostart.ts) as Drizzle-bulk-update precedent.
- **Work items:**
  - [ ] New module `server/services/mcp/default-servers-catalog.ts` exporting `DEFAULT_MCP_CATALOG: DefaultMcpEntry[]` where each entry has `seedKey`, `name`, `command`, `args`, `env` (env-var *names*, not values), `requiredSecrets: string[]`, `autoStartOnConfigure: boolean`.
  - [ ] New module `server/services/mcp/catalog-sync.ts` exporting `async function syncDefaultCatalog()` that, for each catalog entry, `INSERT ... ON CONFLICT (seed_key) DO NOTHING` via Drizzle. Returns `{ inserted, alreadyPresent }` counts.
  - [ ] Migration `db/migrations/0040_seed_default_mcp_servers.sql` performs the same INSERTs at install time so a fresh DB is populated even before the server boots.
  - [ ] Wire `syncDefaultCatalog()` into the server startup path in `server/index.ts`, gated by `readFeatureFlags(process.env).defaultMcp`. Run *after* `recoverErroredServers()` so a failed sync never blocks supervisor startup.
  - [ ] Helper `needsConfig(server: MCPServer): boolean` → true if any `requiredSecrets` env var on the row is empty. Lives next to the catalog module.
- **API additions:** none in this phase.
- **Schema changes:** migration `0040_seed_default_mcp_servers.sql` — 11 `INSERT INTO mcp_servers (seed_key, name, command, args, env, status, auto_restart, max_restarts) VALUES (...) ON CONFLICT (seed_key) DO NOTHING` rows.
- **Acceptance:**
  - Fresh install: `mcp_servers` contains 11 default rows after `npm run db:push`, all with `status='stopped'`.
  - Existing install with `FF_DEFAULT_MCP_SERVERS=true` boots and gains any rows that were not previously present, without mutating user-edited rows.
  - Re-running migrations is idempotent — no duplicate rows, no overwrites.
- **Effort:** M. **Flag:** `FF_DEFAULT_MCP_SERVERS`.

## Engineering Scaffold — Phase 3: Managed-lifecycle API

- **Goal:** Expose the catalog through the existing `/api/v1/mcp-servers` surface and protect managed rows from accidental loss, while supporting "reset to catalog" and "configure secrets" flows.
- **Reuses:** [`server/api/v1/mcp-servers.ts`](../../../server/api/v1/mcp-servers.ts) (extend, do not replace); `logAudit()` helper already used by every existing endpoint; the catalog module from Phase 2.
- **Work items:**
  - [ ] Extend [`server/api/v1/mcp-servers.ts`](../../../server/api/v1/mcp-servers.ts) with the endpoints listed under **API additions** below.
  - [ ] Modify the existing `DELETE /:id` handler to refuse deletion when the row has a non-null `seed_key` unless `?force=true` is supplied; on force-delete, log a `mcp.default.force_deleted` audit event.
  - [ ] Add `PATCH /:id/secrets` `[admin]` — accepts `{ env: Record<string,string> }`, merges into existing `env` jsonb (does not overwrite unrelated keys), redacts incoming values from response. This is the write-side of the "configure" flow used by the dialog in Phase 4.
  - [ ] Reset endpoint resets `command`, `args`, and the *keys* of `env` from the catalog but preserves any present secret *values* unless `?wipeSecrets=true` is passed.
- **API additions:**
  - `GET /api/v1/mcp-servers/catalog` `[admin, operator]` — returns `[{ seedKey, name, command, args, requiredSecrets, installed: boolean, serverId: uuid|null, needsConfig: boolean }, ...]`.
  - `POST /api/v1/mcp-servers/catalog/sync` `[admin]` — invokes `syncDefaultCatalog()`; returns `{ inserted, alreadyPresent }`.
  - `POST /api/v1/mcp-servers/:id/reset` `[admin]` — resets a managed row to its catalog defaults; 400 if `seed_key IS NULL`.
  - `PATCH /api/v1/mcp-servers/:id/secrets` `[admin]` — merges secret env vars; never echoes plaintext.
- **Schema changes:** none.
- **Acceptance:**
  - `GET /catalog` returns 11 entries with accurate `installed`/`needsConfig` flags on a partially configured install.
  - `POST /catalog/sync` is safe to call repeatedly; second call reports `inserted: 0`.
  - `DELETE /:id` on a managed row returns 409 without `?force=true`; with the flag, deletes and audits.
  - `POST /:id/reset` restores command/args from catalog without leaking previously stored secret values into responses.
- **Effort:** M. **Flag:** `FF_DEFAULT_MCP_SERVERS`.

## Engineering Scaffold — Phase 4: Frontend surface

- **Goal:** Surface the catalog in the existing MCP UI, render a managed/needs-config badge on bundled servers, and provide install/reset/configure actions.
- **Reuses:** [`client/src/hooks/useMCPServers.ts`](../../../client/src/hooks/useMCPServers.ts); existing Agents/WorkflowBuilder/ImportAgentDialog consumers (no breaking changes to the `MCPServer` interface — only additive optional fields).
- **Work items:**
  - [ ] Extend the `MCPServer` interface in [`client/src/hooks/useMCPServers.ts`](../../../client/src/hooks/useMCPServers.ts) with optional `seedKey?: string | null` and `needsConfig?: boolean`.
  - [ ] New hook `client/src/hooks/useMcpCatalog.ts` — fetches `GET /catalog`; exposes `{ entries, sync, reset, configure }` mutations.
  - [ ] New component `client/src/components/mcp/DefaultServersPanel.tsx` — table of catalog entries with status pill (`Installed` / `Needs config` / `Not installed`) and per-row actions: **Install** (POST sync), **Configure** (open dialog), **Reset**, **Start/Stop** (reuse existing `/start` and `/stop` endpoints).
  - [ ] New dialog `client/src/components/mcp/ConfigureSecretsDialog.tsx` — renders one masked text input per `requiredSecrets` entry; PATCHes `/secrets`. Display existing values as `••••${last4}` only — never plaintext.
  - [ ] Embed `DefaultServersPanel` at the top of the existing MCP server page (or wherever `useMCPServers` is currently consumed) behind a `useFeatureFlag("defaultMcp")` check.
  - [ ] Managed rows show a subtle `Default` chip in any list that renders them; delete button is hidden unless the operator opens the row's overflow menu and confirms.
- **API additions:** none beyond Phase 3.
- **Schema changes:** none.
- **Acceptance:**
  - With `FF_DEFAULT_MCP_SERVERS=true`, the panel lists all 11 catalog entries on a fresh install.
  - Configuring a Tavily key flips its status pill from "Needs config" to "Installed" and unlocks the Start action.
  - Reset on a managed row restores command/args without wiping the secret already stored.
  - Existing user-created MCP rows continue to render with no `Default` chip and full delete/edit affordances.
  - Lint + typecheck pass; no regressions in `Agents.tsx` / `WorkflowBuilder.tsx` consumers.
- **Effort:** M. **Flag:** `FF_DEFAULT_MCP_SERVERS`.
