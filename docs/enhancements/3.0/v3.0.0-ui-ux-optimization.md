# v3.0 — UI/UX Optimization

End-to-end UI/UX overhaul targeting visual consistency, accessibility, perceived performance, and information density across all 29 application pages. Establishes a documented design system and ports the existing surface to it incrementally without breaking feature work.

This plan was drafted using the `ui-ux-pro-max` skill (design-system + UX/React domains) and audited against the current `client/src/` tree (Tailwind + Radix + shadcn-style primitives, dark-mode via `class`).

---

## Goals

1. **Consistency** — every page renders through the same primitives (PageHeader, Card, Button, Table) with the same spacing rhythm and type scale.
2. **Accessibility** — meet WCAG 2.2 AA across light + dark themes; keyboard- and screen-reader-complete.
3. **Perceived performance** — replace spinner-only loading with skeletons; eliminate layout shift on data load.
4. **Information density** — operator UI (Targets / Vulnerabilities / Agents / Operations) is data-dense by design; refine without sacrificing scannability.
5. **Operator identity** — adopt a deliberate "red team console" aesthetic (semi-dark default, Fira-family typography, restrained motion).

Non-goals: rewriting business logic, adding new feature pages, replacing wouter / TanStack Query.

## Design System (v3.0)

Persisted as `docs/enhancements/3.0/design-system/MASTER.md` (see Phase 1).

### Pattern
Real-time operations console — data-dense panels, status colors prominent, primary CTAs minimal. Optimized for analyst workflows, not marketing/conversion.

### Theme Strategy
- **Default**: semi-dark ("graphite") — easier on long sessions, matches red-team operator expectation.
- **Variants**: `light`, `dark` (current shadcn dark), and new `graphite` (default).
- Theme is a CSS variable swap; component code never branches on theme.

### Color Tokens (additions to `index.css`)
Extend existing tokens — do not replace. New semantic + severity scales:

```
--success:        142 76% 36%   /* emerald-600 */
--success-fg:     0 0% 100%
--warning:        38 92% 50%    /* amber-500 */
--warning-fg:     20 14% 4%
--info:           199 89% 48%   /* sky-500 */
--info-fg:        0 0% 100%

--sev-critical:   0 84% 60%
--sev-high:       16 95% 55%
--sev-medium:     38 92% 50%
--sev-low:        199 89% 48%
--sev-info:       215 16% 55%
```

Mapped through Tailwind config with the same `hsl(var(--token))` pattern. All page-level `text-red-500` / `bg-amber-400` are migrated to these semantic classes.

### Typography
- **Headings**: Fira Sans (currently no custom font — pages fall back to `ui-sans-serif`).
- **Body**: Fira Sans.
- **Mono / code / data tables**: Fira Code (tabular numerals for IPs, ports, CVE IDs, durations).
- Type scale: 12 / 14 / 16 / 18 / 20 / 24 / 30 / 36. Body floor 14px (operator console accepts denser body than consumer apps); never below 12px and only for badges/kbd.
- Mobile body baseline raised to 16px to prevent iOS Safari auto-zoom on inputs.

### Spacing
8pt rhythm. Page padding: `px-4 sm:px-6 lg:px-8`. Section gap: `space-y-6`. Card body padding: `p-4 sm:p-6`. No arbitrary `px-3` or `gap-7`.

### Radius
- `--radius` stays `0.5rem` (8px) for cards/buttons.
- `2px` for badges, `9999px` for status dots and pill filters.

### Elevation
Three-tier shadow scale only:
- `shadow-none` (in-flow surfaces),
- `shadow-sm` (cards, panels),
- `shadow-lg` (overlays: dialog, popover, command palette).
Random `shadow-md` / `shadow-xl` on pages is migrated.

### Motion
- Default duration 150–200ms, easing `ease-out` on enter / `ease-in` on exit.
- All transitions go through `transition-colors` / `transition-opacity` (never `transition-all`).
- `prefers-reduced-motion` respected globally via `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 1ms !important; transition-duration: 1ms !important; } }`.

## Phased Plan

Sequenced so each phase ships independently behind a feature flag where reasonable. Each phase lands as one PR.

### Phase 1 — Design System Foundation
**Outcome**: tokens, primitives, and documentation exist. No page changes yet.

- Author `docs/enhancements/3.0/design-system/MASTER.md` from the skill output above.
- Extend `client/src/index.css` with semantic + severity tokens; add `.graphite` theme class.
- Extend `tailwind.config.ts` to expose new tokens (`success`, `warning`, `info`, `sev-*`).
- Add fonts: `<link>` in `client/index.html` for Fira Sans + Fira Code with `display=swap`; preload only weight 400 + 600 of Fira Sans.
- Add primitives to `client/src/components/ui/`:
  - `skeleton.tsx` — shimmer block, respects reduced-motion.
  - `empty-state.tsx` — icon + title + description + action slot.
  - `status-dot.tsx` — semantic status indicator (`success | warning | error | info | neutral`).
  - `severity-badge.tsx` — uses `--sev-*` tokens; colorblind-safe (adds icon + label, not color alone).
- Add `@media (prefers-reduced-motion: reduce)` global override to `index.css`.
- Tests: snapshot the primitives; visual smoke via Storybook *not* in scope (add backlog item).

**Success metric**: tokens + primitives importable; CI green; zero page changes.

### Phase 2 — Layout Shell
**Outcome**: shell (Sidebar, Header, MainLayout) consistent and accessible.

- `Header.tsx`: bump mobile icon buttons to `h-11 w-11` (44px); add `aria-label` to all icon-only buttons (audit shows ~5 missing).
- `Sidebar.tsx`: add `:focus-visible` ring to nav `Link` items; ensure tab order matches visual order; add `aria-current="page"` on active link; `role="navigation"` + `aria-label="Primary"` on `<aside>`.
- `MainLayout.tsx`: replace `pt-16` math with CSS variable `--header-h: 64px` to keep header height and main-content offset in sync. Add `min-h-dvh` (mobile viewport units fix).
- Sidebar group disclosure: animate chevron via `transition-transform` (currently jumps); preserve `prefers-reduced-motion`.
- Add a skip link (`Skip to main content`) at the top of `MainLayout`.

**Success metric**: full keyboard navigation from page load → sidebar → main content with no mouse; axe-core CLI reports 0 violations on shell.

### Phase 3 — Page Header & Empty/Loading States
**Outcome**: every page uses the same header, the same skeleton, and the same empty state.

- Adopt `PageHeader` on all 29 pages. Standardize on: `icon`, `title`, optional `description`, `actions` (right-aligned). Remove ad-hoc `<h1>` patterns.
- Replace 46 `Loader2` blocking spinners with `<Skeleton />` for first-paint loading. Keep `Loader2` only for inline button-disabled states.
- Replace ad-hoc "no data" copy with `<EmptyState />`. Audit each page for 1 standardized empty per data view.
- Reserve fixed dimensions on async cards/images so `CLS < 0.1`.

**Success metric**: 0 `animate-spin` in `pages/` for first-paint; 100% `PageHeader` adoption.

### Phase 4 — Data Density Pass (Tables, Filters, Density Toggle)
**Outcome**: operator tables are scannable, sortable, filterable, and have a density toggle.

- Wrap every `<Table>` in `overflow-x-auto` (Targets, Vulnerabilities, Agents, Tools, Surface Assessment, etc.).
- Add density toggle on `Targets` / `Vulnerabilities` / `Agents`: Comfortable (`py-3`) / Compact (`py-2`) / Dense (`py-1.5`), persisted to `localStorage`.
- Tabular figures for numeric columns: `font-variant-numeric: tabular-nums` via a `tabular-nums` utility class on td/th.
- Sortable headers must announce `aria-sort` state.
- Bulk select + bulk action bar on Targets and Vulnerabilities (currently single-row only).
- Virtualize lists ≥ 200 rows (Agents table, Implants list) with `@tanstack/react-virtual`.

**Success metric**: Targets / Vulnerabilities / Agents tables scroll smoothly with 5k rows; bulk actions work.

### Phase 5 — Forms, Feedback, Toast Discipline
**Outcome**: forms are predictable; one canonical place per feedback type.

- Audit every form for: visible label (not placeholder-only), inline error below field (`aria-describedby`), `aria-invalid`, focus-on-first-error on submit.
- Standardize submit buttons: disabled + inline spinner during async; success state via toast, never inline.
- Document the toast vs `NotificationCenter` split:
  - **Toast (`sonner`)**: transient feedback for *the current user's action* (saved, copied, failed).
  - **NotificationCenter**: persistent, multi-session events (workflow finished, scan completed, new vuln found).
  - Triggers should not fire both for the same event.
- `<input type="email|tel|search">` everywhere a generic `<input>` is used (mobile keyboard).
- Autocomplete attributes on login + profile.

**Success metric**: form submit success path triggers exactly one feedback surface.

### Phase 6 — Performance & Bundle
**Outcome**: route-level code splitting; faster first paint on slow connections.

- Convert each page in `App.tsx` to `React.lazy()`; wrap `<Switch>` body in `<Suspense fallback={<Skeleton page />} >`.
- Preload heavy routes on hover/focus of sidebar links (`onMouseEnter={() => import('@/pages/Agents')}`).
- Dynamic-import heavy in-page components: `WorkflowDetailsDialog`, attack flow builder, CVSS calculator, markdown editor — only when triggered.
- Bundle audit pass with `vite-bundle-visualizer`; remove unused Radix primitives.
- Move `Agents.tsx` (2,049 lines) into a folder with sub-components: `pages/agents/{index.tsx, AgentsTable, AgentDetailDrawer, CreateAgentDialog, ...}`. Pure refactor, no behavior change.

**Success metric**: initial route JS < 250 KB gzipped (current uncached; measure baseline first).

### Phase 7 — Charts & Data Visualization
**Outcome**: dashboard and surface-assessment charts read clearly in both themes and are accessible.

- Define a chart color palette (`--chart-1` through `--chart-8`) with WCAG-AA pairs against background.
- Severity charts use `--sev-*` tokens (consistent with badges).
- All charts: visible legend, `aria-label` summarizing the insight, tooltip on hover *and* on focus (keyboard).
- Responsive: charts re-flow on `< 768px` (horizontal bar instead of vertical when labels are long).
- Empty state per chart (no broken/empty axes).

**Success metric**: every chart passes a keyboard-only review; SR users get a text summary.

### Phase 8 — Accessibility & QA Gate
**Outcome**: documented baseline that subsequent PRs cannot regress.

- `npm run a11y` script: `axe-playwright` against the 10 highest-traffic pages.
- Lighthouse CI on the same set: a11y ≥ 95, perf ≥ 80 on a throttled run.
- Manual test pass at 375 / 768 / 1024 / 1440px and at largest browser zoom.
- Documented checklist in `docs/DEPLOYMENT.md` under "UI Quality Gate".

**Success metric**: CI fails the build on axe violations and Lighthouse a11y regressions.

## Migration Strategy

- **Per-page conversion** in phase 3 onward is by-PR, two pages per PR, ordered by traffic: Dashboard → Operations → Targets → Vulnerabilities → Agents → Surface Assessment → Reports → Tools → Empire → Implants → frameworks → settings/profile/users.
- A page is "converted" only when it adopts `PageHeader`, replaces spinner-only loading with `Skeleton`, replaces ad-hoc empty copy with `EmptyState`, and uses semantic color tokens (no `text-red-*` / `bg-amber-*` literals).
- A checklist in the design-system MASTER doc tracks per-page conversion status.

---

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Token rename breaks downstream code. | Keep existing tokens; only add new ones. Codemod (`jscodeshift`) for the `text-red-500` → `text-destructive` migration. |
| Skeleton replacing spinner feels slower on fast networks. | Show skeleton only after 100ms (`useDelayedFlag`); skip on cache hits. |
| Bundling 29 lazy routes hurts navigation latency. | Preload-on-intent on sidebar hover/focus. |
| Operator users dislike forced theme change. | `graphite` as default is gated behind `FF_UI_V3_GRAPHITE`; user preference always wins. |
| Density toggle breaks copy/paste from tables. | Persist preference per user, default Comfortable. |
| Refactoring `Agents.tsx` (2049 lines) introduces regressions. | Pure code-split, no logic edits; rely on existing tests + manual smoke per acceptance. |
