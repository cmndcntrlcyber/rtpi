# v3.1.1 — Observability & Logging

**Grade: D** | Target: B | Priority: 1 (highest)

## Overview

All logging is `console.log`/`console.error` with ad-hoc prefixes (`[Metasploit]`, emoji decorators). No structured JSON output, no log levels enforced, no logging library. No Prometheus/StatsD metrics. No Sentry or error aggregation. No request correlation IDs or OpenTelemetry tracing. Audit trail exists (`auditLogs` table) but only covers API route access — tool executions, C2 operations, and credential access are unaudited.

## Evidence

- Every service uses raw `console.*`: Metasploit (`console.log(\`[Metasploit] Executing: ...\`)`), BBOT (`console.log(\`Starting BBOT scan\`)`), Nuclei, Empire, MCP Server Manager — all ad-hoc.
- No structured JSON output means log aggregation tools (ELK, Loki) cannot parse fields.
- No `X-Request-ID` or correlation headers — distributed traces across agent→tool→container calls are impossible.
- No Prometheus client — tool execution duration, scan counts, and error rates are not collected.
- `auditLogs` table covers API route access but misses tool executions, C2 operations, and credential access.

## Implementation Notes

### Pino Logger Setup

Create `server/lib/logger.ts` exporting a configured pino instance. Replace all `console.log` calls with `logger.info()`, `console.error` with `logger.error()`, etc. Pino outputs structured JSON by default and is the fastest Node.js logger.

### Correlation ID Middleware

Generate a UUID per request, attach to `req.id`, include in all log calls and response headers. Pass through to tool executor and agent calls so the full chain is traceable.

### Prometheus Metrics

Use `prom-client` with a `/metrics` endpoint. Key histograms: `tool_execution_duration_seconds{tool,status}`, `scan_duration_seconds{scanner,target_type}`. Key counters: `tool_executions_total{tool,status}`, `agent_workflow_completions_total{status}`.

### Audit Trail Extension

Add `logAudit()` calls to: `metasploit-executor.ts` (on execute), `bbot-executor.ts` (on scan start/complete), `nuclei-executor.ts` (on scan start/complete), `empire-executor.ts` (on task execute, credential harvest), `nmap-executor.ts` (on scan start/complete).
