# v3.1.10 — MCP Server Management

**Grade: A-** | Target: A | Priority: 10

## Overview

Full server lifecycle: spawn with 30s timeout, graceful shutdown (SIGTERM → 5s → SIGKILL), auto-recovery of errored/stale servers on startup, exponential backoff restarts. Preflight checks prevent bad spawns. CRUD API with secret redaction. Default catalog sync via `INSERT ... ON CONFLICT DO NOTHING`. 4 test files. Gaps: no per-server response time metrics, no capability drift detection, no bulk operations.

## Evidence

- **Lifecycle** (`server/services/mcp-server-manager.ts`): Spawn with 30s timeout, shell execution for npx/npm commands, graceful shutdown (SIGTERM → 5s → SIGKILL), auto-recovery of errored/stale servers on boot, exponential backoff restarts (2000ms delay).
- **Preflight checks**: Prevent bad spawns (missing binaries, invalid configs). Self-healing path creation.
- **CRUD API** (`server/api/v1/mcp-servers.ts`): List, get by ID, create (with preflight + validation), update, delete. Secrets redacted in responses (`••••<last4>`). Catalog endpoint. Repair known-bad rows.
- **Catalog sync** (`server/services/mcp/catalog-sync.ts`): `INSERT ... ON CONFLICT (seed_key) DO NOTHING` — never overwrites operator edits.
- **Health monitoring**: 30-second interval process exit detection.
- **Tests**: `mcp-servers.test.ts`, `mcp-catalog.test.ts`, `mcp-preflight.test.ts`, `agent-loop-mcp.test.ts`.
- **Gaps**: No per-server response time metrics, no capability drift detection (alert when tools/resources change), no bulk operations (start/stop multiple).

## Implementation Notes

### Bulk Operations (Item 1)

Add `POST /api/v1/mcp-servers/bulk/start` and `POST /api/v1/mcp-servers/bulk/stop` accepting `{ ids: string[] }`. Iterate and return per-server results. Rate-limit to prevent resource exhaustion.

### Response Time Metrics (Item 2)

Time each tool call and probe. Store rolling averages in the `mcpServers` table (add `avgResponseMs`, `p95ResponseMs` columns) or emit Prometheus histograms if observability stack is in place (see [v3.1.1](v3.1.1-observability-logging.md)).

### Capability Drift Detection (Item 3)

After each capability refresh in `agent-mcp-connector.ts`, compare the new tool/resource list against the previously stored one. If tools were added or removed, log a warning and optionally emit a notification. Store the last-known capability set in the `mcpServers` table.
