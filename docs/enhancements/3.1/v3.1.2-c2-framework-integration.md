**Grade: C-** | Target: B | Priority: 2

## Overview

Empire integration is production-ready (OAuth2 + legacy auth, listener/stager/agent CRUD, credential sync). But Sliver and Havoc have schema-level enums only — no executor, no routes, no tests. Rust-Nexus has early WebSocket + mTLS scaffolding but implementation is incomplete (no audit logging, telemetry storage opaque). Empire API routes lack auth middleware.

- **Test coverage**: Only `empire-executor.test.ts` (mocked auth flows). Zero for Rust-Nexus, Sliver.

## Implementation Notes

### Empire Auth Middleware

Wrap all Empire routes with `ensureAuthenticated` and appropriate `ensureRole('admin', 'operator')`. This is a one-line addition per route group but is currently missing entirely.

### Sliver Executor

Follow the Empire executor pattern. Sliver exposes a gRPC API — use `@grpc/grpc-js` or shell out to the `sliver-client` CLI. Key operations: implant management, listener CRUD, task execution. Schema tables for Sliver sessions and tasks should mirror the Empire pattern.

### Rust-Nexus Completion

The WebSocket + mTLS transport layer exists. What's missing: (1) persisting telemetry payloads to DB, (2) audit logging for implant registration and task assignment, (3) task result storage and retrieval via API.
