# v3.1.4 — Security Posture

**Grade: C+** | Target: A- | Priority: 4

## Overview

XSS vulnerability in `MarkdownEditor.tsx` — `dangerouslySetInnerHTML` with unsanitized `renderMarkdown()` output. CSRF tokens stored in an in-memory `Map` (doesn't scale, no TTL). `SESSION_SECRET` defaults to an unsafe string without failing in production. Input validation uses Zod in some routes but many parse `req.body` directly. Helmet.js enabled but no explicit Content-Security-Policy configuration.

## Evidence

- **XSS (CRITICAL)**: `client/src/components/markdown/MarkdownEditor.tsx:86` uses `dangerouslySetInnerHTML={{ __html: renderMarkdown(value) }}`. The `renderMarkdown()` function uses regex replacements that do not sanitize HTML. User input like `<img src=x onerror="alert(1)">` executes. No DOMPurify or sanitization library is present.
- **CSRF**: `server/middleware/csrf.ts` stores tokens in an in-memory `Map`. Not Redis-backed (single-server only). No TTL — tokens never expire. Basic LRU cleanup at size > 1000.
- **Session secret**: `server/auth/session.ts` defaults `SESSION_SECRET` to `"change-this-secret-in-production"`. No guard against this default in production.
- **Input validation**: Zod present in some routes (`offsec-rd-tools.ts`, `memory.ts`, `agent-chat.ts`) but many routes parse `req.body` fields directly without schema validation.
- **Helmet**: Enabled with defaults but no custom `contentSecurityPolicy` configuration.
- **Positives**: Bcrypt factor 12, API keys SHA256-hashed, Drizzle ORM (parameterized queries), rate limiting on auth routes, no hardcoded secrets found.

## Implementation Notes

### XSS Fix (Item 1)

```bash
npm install dompurify @types/dompurify
```

In `MarkdownEditor.tsx`, import DOMPurify and sanitize before rendering:
```tsx
import DOMPurify from 'dompurify';
// ...
<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(renderMarkdown(value)) }} />
```

### Session Secret Guard (Item 2)

In `server/auth/session.ts`, add before session middleware creation:
```typescript
if (process.env.NODE_ENV === 'production' && sessionSecret === 'change-this-secret-in-production') {
  throw new Error('SESSION_SECRET must be changed from default in production');
}
```

### CSP via Helmet (Item 3)

Configure `helmet({ contentSecurityPolicy: { directives: { defaultSrc: ["'self'"], scriptSrc: ["'self'"], styleSrc: ["'self'", "'unsafe-inline'"], imgSrc: ["'self'", "data:", "blob:"] } } })`.

### CSRF Redis Migration (Item 4)

Replace `Map` with Redis hash. Key: `csrf:<token>`, value: user session ID, TTL: 3600s. Use existing Redis connection from session store.
