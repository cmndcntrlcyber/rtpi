# v3.1.5 — Docker Infrastructure

**Grade: B-** | Target: A- | Priority: 5

## Overview

25 containers have real healthchecks. 10 containers use stub checks (`CMD-SHELL "true"` or `echo "healthy"`) that always report healthy — `deploy-verify.sh` trusts these and passes broken containers. 6 long-running services (`rtpi-workbench-frontend`, `kasm-manager`, `kasm-guac`, `kasm-share`, `empire-proxy`, `rtpi-sysreptor-caddy`) have no healthcheck at all. Main `Dockerfile` also has no `HEALTHCHECK`.

## Evidence

- **Real healthchecks (25)**: PostgreSQL, Redis, Kasm DB/Redis, MongoDB, Empire, Workbench API, mem0, orchestrator, Ollama, Kasm workspace images, and others with proper HTTP/CLI checks.
- **Stub healthchecks (10)**:
  - `rtpi-tools`: `echo "healthy"` — reports healthy even if all tools are missing
  - 8+ OffSec agents (maldev, azure-ad, burp, empire, framework, fuzzing, llm-sec, research, cloud): `CMD-SHELL "true"` — always passes
- **Missing healthchecks (6 long-running)**: `rtpi-workbench-frontend` (port 3020), `kasm-manager`, `kasm-guac`, `kasm-share`, `empire-proxy` (nginx on 1337), `rtpi-sysreptor-caddy`
- **Main Dockerfile**: No `HEALTHCHECK` directive — standalone container deployment would have no health signal
- **Impact**: `deploy-verify.sh` trusts Docker health status, so stub/missing checks create false confidence in deployment health

## Repair Items

| # | Item | Effort | Files |
|---|------|--------|-------|
| 1 | Add `HEALTHCHECK` to main `Dockerfile` | S | `Dockerfile` |

## Implementation Notes

### Main Dockerfile (Item 1)

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
    CMD curl -f http://localhost:3001/api/v1/health || exit 1
```

### Stub Replacement (Item 2)

**rtpi-tools**: Replace `echo "healthy"` with `nmap --version > /dev/null 2>&1` (verifies a core tool binary exists).

**OffSec agents**: Replace `CMD-SHELL "true"` with PID-based checks. Each agent runs a long-lived process — check it's alive:
```dockerfile
HEALTHCHECK --interval=60s --timeout=10s --retries=3 \
    CMD kill -0 1 || exit 1
```
For agents with internal HTTP endpoints, use `curl -f http://localhost:<port>/` instead.

### Missing Healthchecks (Item 3)

Add to `docker-compose.yml`:

| Container | Check |
|-----------|-------|
| `rtpi-workbench-frontend` | `curl -sf http://localhost:3020/` |
| `kasm-manager` | `curl -sf http://localhost:8080/` or internal ping |
| `kasm-guac` | `curl -sf http://localhost:4822/` |
| `kasm-share` | Internal service ping |
| `empire-proxy` | `curl -sf http://localhost:1337/` |
| `rtpi-sysreptor-caddy` | `curl -sf http://localhost:80/` |
