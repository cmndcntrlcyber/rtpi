## Implementation Notes

### Retry Logic (Item 1) — DONE

Both BBOT and Nmap executors call `dockerExecutor.execWithRetry()` which provides max 2 retries with exponential backoff (1s, 2s). Validation errors (dangerous patterns, command not found) are not retried. Transient container failures are retried.

### Metasploit CVE Extraction (Item 2) — DONE

`extractVulnMetadata()` scans module path and output text for:
- `CVE-\d{4}-\d{4,}` patterns (deduplicated, uppercased)
- `CWE-\d+` patterns (deduplicated, uppercased)
- Explicit CVSS scores from output text
- Fallback: rank-to-CVSS mapping (excellent=9.8, great=8.5, good=7.0, normal=5.0, average=4.0, low=2.0)

Results populate `ExecutionResult.cveIds`, `.cweIds`, `.cvssScore` and `parseModuleInfo().cveIds/cweIds/cvssScore`.

### Unit Tests (Item 3) — DONE

Test files: `metasploit-executor.test.ts` (245 lines), `bbot-executor.test.ts` (223 lines), `nmap-executor.test.ts` (215 lines), `nuclei-executor.test.ts` (279 lines), `empire-executor.test.ts`.

### Multi-Container Discovery (Item 4) — DONE

`tool-discovery-service.ts` now has two manifest arrays:
- `DOCKERFILE_TOOLS` (20 tools in `rtpi-tools`)
- `SPECIALIZED_CONTAINER_TOOLS` (65+ tools across 9 specialized containers)

`discoverTools()` groups tools by container, checks container availability once, then probes each tool. Unavailable containers are logged and their tools marked as not installed.

### Centralized Container List (Item 5) — DONE

`TOOL_CONTAINERS` is exported from `tool-discovery-service.ts` and imported by `multi-container-executor.ts` in `getContainerStatuses()`. Single source of truth, no hardcoded lists.

### registerContainerTool() (Item 6) — DONE

Exported function for programmatic tool registration. Upserts to `tool_registry` table, fires skill generation for new entries. Pattern for adding a new tool:
1. Add entry to `SPECIALIZED_CONTAINER_TOOLS` in `tool-discovery-service.ts`
2. The refresh endpoint auto-discovers and registers it
3. Or call `registerContainerTool()` directly
