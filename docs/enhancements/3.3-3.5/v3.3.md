# v3.3 — Refactor RTPI to Leverage Nexus-Harness

**Created:** 2026-07-30
**Status:** Planning
**Priority:** HIGH — eliminates 17 container images (~40 GB aggregate), replaces Python/LangGraph orchestrator with native Rust agent loop, expands nexus-harness independently to absorb tool capabilities that RTPI containers currently provide

---

## Overview

RTPI currently maintains 17+ specialized Docker containers, each shipping its own copy of offensive tools, a per-container MCP server entrypoint, and a shared `offsec-base` image built on Ubuntu 22.04 with Go, Node, Python, Rust, and Java runtimes. The LangGraph orchestrator (`services/orchestrator/`) dispatches tool execution via `docker exec` into these containers. This architecture is expensive (multi-GB images per container, slow builds, fragile inter-container networking), hard to maintain (every tool addition requires a Dockerfile change, base image rebuild, and compose reconfiguration), and redundant — multiple containers ship overlapping tools (nmap in research-agent, azure-ad-agent, and empire-agent; Impacket in empire-agent and azure-ad-agent; nuclei in fuzzing-agent and burp-agent).

nexus-harness already provides 118+ offense skills across 13 categories, 10 specialized subagents, 4 slash commands (`/engage`, `/recon`, `/hunt`, `/scope`), and 3 MCP servers (Playwright, Chrome DevTools, Burp) — all running independently inside a single nexus-kali container with the full Kali Linux tool suite pre-installed. Rather than maintaining a parallel tool infrastructure in RTPI, this enhancement identifies which container tools nexus-harness already covers, plans independent nexus-harness enhancements to close gaps, and deprecates RTPI's redundant container infrastructure and LangGraph orchestrator. **All nexus-harness enhancements operate independently of RTPI and are usable standalone via CLI, MCP, or programmatic API.** RTPI retains its role as administrative frontend/GUI — consuming nexus-harness capabilities, not defining them.

Work Stream 1 (Tool Catalogue) audits all RTPI containers, classifies each tool against nexus-harness coverage, and produces per-tool enhancement plans under `3.4/` for every gap. Work Stream 2 (Intelligence × Nexus-Swarm) plans the integration of the nexus-swarm multi-agent consensus engine into Intelligence-category operations — offensive R&D, CTI, framework assessments, and reporting — as standalone nexus-harness capabilities that RTPI's GUI surfaces without modification. v3.5 captures follow-on work that emerges from both streams.
